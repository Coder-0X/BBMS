# BloodBank LIS — Production Deployment Runbook

## Stack

| Layer | Technology |
|---|---|
| Application | Django 5.x (Gunicorn WSGI) |
| Database | PostgreSQL 15+ |
| Key management | HashiCorp Vault (dev fallback: SECRET_KEY-derived key) |
| Web / TLS | Nginx reverse proxy |
| Process management | systemd |
| Alert scheduler | cron / OS Task Scheduler |

---

## 1. Server prerequisites

```bash
# Ubuntu 22.04 LTS
sudo apt update && sudo apt install -y python3.11 python3.11-venv postgresql-15 nginx git
```

---

## 2. PostgreSQL setup

```sql
-- Run as postgres superuser
CREATE DATABASE bloodbank;
CREATE USER bloodbank_user WITH PASSWORD 'CHANGEME_strong_password';
GRANT ALL PRIVILEGES ON DATABASE bloodbank TO bloodbank_user;

-- Restrict the app user from deleting audit logs (append-only enforcement)
REVOKE DELETE, UPDATE ON audit_auditlog FROM bloodbank_user;
```

## 4. Environment file

Create `/opt/bloodbank-app/.env`:

```ini
DEBUG=False
SECRET_KEY=<at-least-64-random-chars>
ALLOWED_HOSTS=your-domain.com,127.0.0.1

DATABASE_URL=postgres://bloodbank_user:CHANGEME@localhost:5432/bloodbank

# HashiCorp Vault (optional — falls back to SECRET_KEY-derived key in dev)
VAULT_ADDR=https://vault.internal:8200
VAULT_TOKEN=<vault-token>
VAULT_MOUNT=secret
VAULT_PATH=bloodbank/field-encryption

# Session security
SESSION_COOKIE_SECURE=True
CSRF_COOKIE_SECURE=True
SECURE_HSTS_SECONDS=31536000

# Time zone
TIME_ZONE=Asia/Dhaka
```

## 7. Gunicorn systemd service

`/etc/systemd/system/bloodbank.service`:

```ini
[Unit]
Description=BloodBank LIS (Gunicorn)
After=network.target postgresql.service

[Service]
User=www-data
Group=www-data
WorkingDirectory=/opt/bloodbank-app
EnvironmentFile=/opt/bloodbank-app/.env
ExecStart=/opt/bloodbank-app/.venv/bin/gunicorn \
    --workers 4 \
    --bind unix:/run/bloodbank/gunicorn.sock \
    --timeout 120 \
    --access-logfile /var/log/bloodbank/access.log \
    --error-logfile /var/log/bloodbank/error.log \
    bloodbank.wsgi:application
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo mkdir -p /run/bloodbank /var/log/bloodbank
sudo chown www-data:www-data /run/bloodbank /var/log/bloodbank
sudo systemctl daemon-reload
sudo systemctl enable --now bloodbank
```

## 8. Nginx configuration

`/etc/nginx/sites-available/bloodbank`:

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    client_max_body_size 10M;

    location /static/ {
        alias /opt/bloodbank-app/staticfiles/;
        expires 7d;
        access_log off;
    }

    location / {
        proxy_pass http://unix:/run/bloodbank/gunicorn.sock;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/bloodbank /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

## 9. Alert scheduler (cron)

The system has no background daemon. Alerts are generated by a management command.

```bash
# Add to crontab: crontab -e (as www-data or a dedicated service user)
*/5 * * * * cd /opt/bloodbank-app && /opt/bloodbank-app/.venv/bin/python manage.py run_alerts >> /var/log/bloodbank/alerts.log 2>&1
0 1 * * *   cd /opt/bloodbank-app && /opt/bloodbank-app/.venv/bin/python manage.py build_daily_facts >> /var/log/bloodbank/analytics.log 2>&1
30 1 * * *  cd /opt/bloodbank-app && /opt/bloodbank-app/.venv/bin/python manage.py check_shortages >> /var/log/bloodbank/shortage.log 2>&1
0 8 * * *   cd /opt/bloodbank-app && /opt/bloodbank-app/.venv/bin/python manage.py donor_engagement >> /var/log/bloodbank/donors.log 2>&1
```

| Command | Purpose | Schedule |
|---------|---------|----------|
| `run_alerts` | Inventory alerts, cold chain, QC, expiry | Every 5 min |
| `build_daily_facts` | Analytics demand facts + KPIs | Nightly 01:00 |
| `check_shortages` | Forecast shortage alerts for next 72h | Nightly 01:30 |
| `donor_engagement` | Lapsed donors, deferral expiry, milestones | Daily 08:00 |

On **Windows Server** (Task Scheduler):
- Program: `C:\path\to\.venv\Scripts\python.exe`
- Arguments: `manage.py run_alerts`
- Start in: `C:\path\to\bloodbank-app\`
- Trigger: Repeat every 5 minutes, indefinitely

## 10. HashiCorp Vault setup (optional but recommended)

```bash
# Start Vault dev server locally for testing
vault server -dev

# In production:
vault kv put secret/bloodbank/field-encryption key=$(openssl rand -hex 32)
```

If Vault is unavailable, the system falls back to deriving an encryption key from `SECRET_KEY`. This is acceptable for development but **not recommended for production** (rotating the key becomes much harder).

## 11. Backup strategy

```bash
# Daily PostgreSQL backup (adjust path and retention)
pg_dump -U bloodbank_user -F c bloodbank > /backups/bloodbank_$(date +%Y%m%d).dump

# Automated backup with pg_dump + cron:
0 2 * * * pg_dump -U bloodbank_user -F c bloodbank | gzip > /backups/bloodbank_$(date +\%Y\%m\%d).dump.gz
```

Keep at least 30 days of backups off-site. The hash-chained audit log is also a recovery mechanism — its integrity can be verified independently.

## 12. Security checklist

- [ ] `DEBUG=False` in production
- [ ] Strong `SECRET_KEY` (64+ random chars)
- [ ] `ALLOWED_HOSTS` set to actual domain only
- [ ] TLS 1.2+ enforced (TLS 1.3 preferred)
- [ ] `SESSION_COOKIE_SECURE=True` and `CSRF_COOKIE_SECURE=True`
- [ ] `SECURE_HSTS_SECONDS=31536000` (1 year)
- [ ] PostgreSQL `bloodbank_user` cannot DELETE from `audit_auditlog`
- [ ] Vault token has narrowest possible policy scope
- [ ] Gunicorn runs as `www-data`, not root
- [ ] Log rotation configured for `/var/log/bloodbank/`
- [ ] Fail2ban or similar for brute-force protection at the Nginx layer
- [ ] Regular `python manage.py check --deploy` passes

## 13. Upgrade procedure

```bash
cd /opt/bloodbank-app
git pull origin main
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
sudo systemctl restart bloodbank
```

Always run `python manage.py migrate` before restarting. Migrations are backward-compatible by convention — never squash migrations that have already been deployed to production.
